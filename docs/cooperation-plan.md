# 合作引导实施计划

目标：让玩家知道共同目标、当前缺口、自己能做什么、个人和 Lands 领地的贡献；不维护独立小队，插件自主运行，不依赖 AI/MCP 在线。正式服不部署。

## 逐项实施与验收
1. 推荐：从尚需完成的资源中选择恰好 requiredCount-completedCount 个，优先背包能够补齐、背包已有、低成本且进度较近的资源。GUI主页行动卡、任务页缺口/背包/已认领；一键仅投入推荐物品数量。完成/已结算/到期任务不可推荐投入；三选四不追收第四种。
2. 认领：个人或有权限的 Lands 领地认领部分缺口，默认最多1小时且不超过任务期限；本人取消，计划不扣资源、不占实际支付预留、不禁止别人贡献。领地只读查询官方API，实时确认领主／信任权限，无成员副本或人数上限；API故障暂停领地认领但不误删计划，个人继续。MySQL共享计划，服务器作用域ULID防冒认。
3. 反馈：成功提交后记录个人首次／补齐／连续参与／总分，以及当次有效领地历史分。改名保持身份，换领地不转移分数；失败／重复不记账，不改变fixed/pool或额外发币。
4. 提醒：新周期/接近完成/成功成果，默认普通提醒10分钟冷却、每任务每类型一次，总计最多3次；完成通知可绕过普通冷却。个人GUI开关，关闭后不记录发送去重。只提示可行动的必要缺口，避免刷屏和点名责罚。通过玩家调度器发个人消息，背包读取仅在玩家线程。
5. 自适应：观察最近最多6期同周期记录，至少3期后生效，每次最多±10%，数量倍率0.5–2.0；失败偏多/活跃明显下降则降低，普遍提前完成/活跃增加则缓慢提高。冷启动1.0。长期失败且低进度的必要资源临时绕开，兼容模板不足回退正常池。仅新自动任务使用；当前目标/期限/策略不变，manual不变。整数物品数量向上取整至少1。

## 工程边界
- 现有边界smoothstep、月上限±比例、CB官方API和原版过渡保持不变。
- 日周月、旧任务/期限、奖励、广播开关、贡献事务和数据库记录保留。
- cooperation.yml v3 保存个人设置、领地选择／历史分、活动、去重、观察与倍率。旧小队只归档、不映射Lands。任务目标仍由quests.yml／MySQL保存。
- 新增MySQL认领表，仅CREATE/补列，不删表。故障不假装共享成功。
- 玩家 /bg guide、/bg lands [select <id>]、/bg reminders 命令后备；成员管理只使用 /lands。控制台 /bg cooperation 只读概览。GUI优先。
- 每个GUI持有资源/任务映射，点击按打开时身份处理；操作时重新检查期限、任务和成员权限。

## 执行
Lands修正版重点验证：官方API只读契约、实时权限／故障保护、GUI只领地入口、稳定身份／历史归属、旧数据归档、个人功能及既有自动运营。一次有界只读审查，修具体缺陷后复测；没有真实Lands插件或真人客户端时明确限制，不沿用旧小队测试数字作为新包证据。

## 完成标准
五项都能从GUI进入、保存后重启有效，默认无需逐项配置；回归与具体运行验证通过；测试包与交付包hash一致、探针排除、隔离服正常停服。真实客户端或经济/全多服并发若未实测明确标注。
